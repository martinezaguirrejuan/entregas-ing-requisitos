## Ingeniería de Requisitos

La Ingeniería de Requisitos (IR) es la disciplina que se encarga de identificar, documentar, analizar y gestionar las necesidades de los usuarios antes del desarrollo del software. Según **IEEE 830**, un requisito bien documentado debe ser: correcto, no ambiguo, completo, consistente, verificable, trazable y modificable.

## Tipos de requisitos

| Tipo | Definición |
|------|-----------|
| **Historia de Usuario (HU)** | Descripción informal de una funcionalidad desde la perspectiva del usuario: *Como [rol], quiero [acción], para [beneficio]*. |
| **Requisito Funcional (RF)** | Capacidad concreta que el sistema debe ofrecer. |
| **Requisito No Funcional (RNF)** | Atributo de calidad del sistema (rendimiento, seguridad, usabilidad) con métricas medibles. |
| **Regla de Negocio (RN)** | Restricción o política que el sistema debe respetar: *SI [condición] ENTONCES [acción]*. |

## Estándares aplicados

- **IEEE 830**: Guía para la especificación de requisitos de software
- **ISO/IEC 25010**: Modelo de calidad del producto software (McCall actualizado)
- **Scrum**: Metodología ágil — uso de historias de usuario y backlog
- **UML 2.x**: Diagramas de casos de uso y actividad

## Inteligencia Artificial en contratos

El uso de modelos de lenguaje grande (LLM) como **LLaMA 3.3 70B** via **Groq AI** permite generar texto legal estructurado y analizar cláusulas contractuales a velocidades impractibles para un humano, democratizando el acceso a servicios legales básicos.
